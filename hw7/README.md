## 1. 問題定義
給定兩個文字字串或檔案序列 $A = (a_1, a_2, \dots, a_N)$ 與 $B = (b_1, b_2, \dots, b_M)$，找出使 $A$ 轉換成 $B$ 所需的最少行編輯操作（保留、新增 `+`、刪除 `-`）。

本專案分別實作以下兩種解法進行對比：
1. **動態規劃（DP）**：基於最長公共子序列（Longest Common Subsequence, LCS）
2. **非動態規劃（Non-DP）**：Myers 差異演算法（Git `git diff` 核心採用的圖論搜尋法）

---

## 2. 演算法原理分析

### 2.1 動態規劃方法：LCS (Longest Common Subsequence)
- **原理**：
  定義狀態 $dp[i][j]$ 為序列 $A[1 \dots i]$ 與 $B[1 \dots j]$ 的最長共同子序列長度。
  - 當 $A[i] == B[j]$ 時：$dp[i][j] = dp[i-1][j-1] + 1$
  - 當 $A[i] \neq B[j]$ 時：$dp[i][j] = \max(dp[i-1][j], dp[i][j-1])$
  填滿 $(N+1) \times (M+1)$ 的矩陣後，從右下角 $dp[N][M]$ 回溯至起點，判定每一列是保留、刪除還是新增。
- **特點**：邏輯直觀，保證找出最優解；但無論兩檔案多麼相似，皆必須完整填完整個表格。

### 2.2 非動態規劃方法：Myers 差異演算法
- **原理**：
  Eugene W. Myers 於 1986 年提出。將比對問題轉化為**編輯網格圖（Edit Graph）的最短路徑問題**：
  - 水平向右移動一格代表「刪除」；
  - 垂直向下移動一格代表「新增」；
  - 遇到相同字元時，可免費沿著「對角線」滑行。
  演算法採用**寬度優先搜尋（BFS）配合貪婪擴展**，依編輯距離 $D = 0, 1, 2, \dots$ 逐層搜尋，並利用對角線編號 $k = x - y$ 進行狀態維護。
- **特點**：演算法的執行時間直接與「相異處多寡」掛鉤，而非檔案總長度。

---

## 3. 複雜度對比

| 評估項目 | 動態規劃 (LCS) | 非動態規劃 (Myers 演算法) |
| :--- | :--- | :--- |
| **時間複雜度** | $O(N \cdot M)$ | **$O((N + M) \cdot D)$** （$D$ 為編輯差異數） |
| **空間複雜度** | $O(N \cdot M)$ | **$O(N + M)$**（若搭配分治線性空間版可壓至 $O(N+M)$） |
| **搜尋策略** | 全域窮舉填表 (Tabulation) | 貪婪廣度優先搜尋 (Greedy BFS on Edit Graph) |
| **最差情況** | 始終為 $O(N \cdot M)$ | 當兩檔案完全不同 ($D \approx N+M$) 時退化為 $O((N+M)^2)$ |
| **最佳情況** | 仍需 $O(N \cdot M)$ 填表 | 兩檔案完全相同 ($D=0$) 時只需 **$O(N)$** |

---

## 4. 總結與比較
1. **小改動情境（$D \ll N+M$）**：
   在實際軟體開發（如 Git 版本控制）中，兩次提交通常只修改少數幾行程式碼。Myers 演算法能以極快的速度 $O((N+M) \cdot D)$ 完成比對，遠勝於需要填滿整張矩陣的 LCS DP 法。
2. **記憶體效率**：
   LCS 需依賴二維陣列記錄回溯方向，在面對數萬行的超大文字檔時極易耗盡記憶體；Myers 演算法僅需追蹤當前對角線的最遠端點，空間利用率遠高於 LCS。
3. **結論**：
   動態規劃 LCS 是教科書中最標準的通用基礎解法，而 Myers 演算法透過結合圖論最短路徑與貪婪對角線跳躍，成為現代差異比對工具的最佳實踐。
